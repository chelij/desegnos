# Desegnos editor design

The editor is a full blank workspace with text boxes placed directly where the user wants something. A screen outline is a reference guide inside that workspace. Users can work above, below, and on either side of it. Each page has its own workspace, reached through browser-style tabs. Positions and sizes communicate placement intent; the agent coordinates the actual website layout.

There are no sidebars, inspectors, layer panels, or area-caption cards. Small floating toolbars and transient popovers are allowed. Placement is visual first; numeric fields may appear in Edit dialogs for precision. Every capability has a visible control; gestures and shortcuts are accelerators, never the only path. The canvas occupies the workspace. One nested menu holds file, editing, page, view, and technical commands. The top bar keeps the project name, AI connection, and generation controls; page tabs sit directly below. Select, Add request, Pan and zoom controls live in a compact floating toolbar at the bottom of the canvas; grid settings remain in the status bar. Copy uses short, ordinary labels. Technical explanations, raw requirements, source, model limits, and diagnostics are available through menus rather than shown by default. Every displayed control performs an implemented operation.

Generate is always visible in an open project and is disabled until a request contains text. Interpretation appears once in a dropdown beside Generate, labelled Flexible / Precise. Fuzzy lets the agent interpret requests and coordinate the composition. Strict follows descriptions, relative placement, and grouping closely while allowing coordinated dimensions and responsive behavior. The setting belongs to the project and frozen generation job; individual text boxes have no modes.

Generate freezes a native job and sends it once with the global setting. Generation never blocks the canvas. Progress lives in a horizontal strip with elapsed time and Cancel while only affected elements blur. The dialog opens only from Details. A validated result appears directly in the workspace with an on-canvas Keep, Undo, Try again and Details bar. Local edits remain possible and stale-source checks remain authoritative. Details exposes the exact requirements, digest, model details, source code, choices and attempts. Progress shows native state and elapsed time; response byte counts stay in technical details. Cancelled or uncertain outcomes explain possible charges in one sentence. A retry requires another explicit paid-send decision and reuses the same frozen request.

Generation feedback stays in the horizontal strip above the website; the optional Details dialog retains its sticky header. Ready to send explains that the AI has not started, with Send and generate visible above the review. Working states show elapsed time from the current operation or native attempt. Plain status text and a ticking timer communicate activity without invented percentages or looping decoration. The same neutral grey surfaces, readable system type and restrained blue primary action keep this feedback part of the editor. Only stage changes are announced automatically; timer and technical byte updates stay quiet for assistive technology.

AI settings live in a dialog. Key entry uses a password field cleared on submission; native system storage or session memory holds the key. The editor displays credential status and access-test results, never the secret. Session storage temporarily overrides a system key. Configuration errors remain visible until the native settings operation resolves them.

Generation methods are explicit: API key or ChatGPT plan. Continue with ChatGPT starts native browser authorization; the editor receives public account status and polls only during a pending sign-in. Saved registrations remain distinct and selectable, with native reconnect, sign-out and storage choices. The first successful plan authorization shows a welcome; Got it records the native acknowledgment, while closing leaves it pending for a later settings refresh. Using ChatGPT plan and Manage usage appear beside relevant controls; a plan-limit failure makes Manage usage the primary action. Only native selectable models appear. ChatGPT review and retry describe the frozen account’s plan or credits, while API-key review keeps its USD estimate and output cap. Switching settings never redirects a prepared job’s authentication.

Candidate review presents real source, request coverage, component conflicts, optional identity proposals and advisory design criticism. Apply accepts the native transaction result; the editor cannot fabricate accepted site state. An opaque sandbox displays registered native preview resources, with page scripts paused until explicitly enabled. Accepted content sits beneath the canvas requests without intercepting authoring input. A separate preview dialog supports interacting with the site. Neither preview receives filesystem, network or editor command privileges.

Double-clicking empty space opens a request. Double-clicking a text element edits its text in place, committing through the existing durable local edit command on Enter or blur and cancelling with Escape. Ask AI is a labelled selection control and Ctrl/Cmd+K shortcut that opens the element request. A single click selects and outlines an actual generated element and dismisses an abandoned empty prompt without opening another one. A floating action bar edits text/link/image/style, replaces, moves, reorders or deletes the selected element locally. Ask AI opens its prompt; these local controls do not call a provider and share durable project Undo/Redo. Dragging a selected element moves it directly; its four corners resize it with the opposite corner anchored. A compact toolbar follows the selection, prefers its top-left and flips below when that avoids covering surrounding content. It shows the element type and a labelled Ask AI action. Tooltips describe other icons. Right-click selects and offers Edit or Generate. Left-drag on empty space pans; Shift+drag draws an area. Ctrl+wheel zooms around the pointer. Selecting another request archives abandoned empty boxes, preserving undo and any scoped decisions. Text selection and typing never initiate placement drags. A selected box exposes small move and resize grips outside the text input. Arrow keys on those grips provide keyboard placement, and Escape from text returns to the move grip. Request text, caret size, focus rings, and grip hit targets remain readable at every zoom level. Text-box dimensions remain authoring hints and do not promise matching generated element bounds.

Use system UI typography for readable native controls, and system monospace for real Markdown source. The user requested grey like Photoshop. Neutral grey chrome in both light and dark themes keeps attention on the website; each base surface has equal red, green and blue channels. This palette direction does not add Photoshop panels or change Desegnos's canvas layout. Text-box surfaces also use neutral greys and follow the page appearance so they remain readable independently of the editor theme. A restrained blue marks the current selection, focus and primary action. Errors use text and a clear outline, not color alone.

The workspace grid starts on, with eight-pixel spacing. Users can choose spacing in pixels or percentages of the screen guide, and turn grid visibility, snapping, or rulers on and off independently. Horizontal and vertical rulers default to pixels relative to the guide, including positions outside it. Percent is available in settings independently of grid spacing units. Alignment guides and a small selection measurement appear during placement. The guide and accepted preview have separate extents so a long site can extend below its reference screen. Small radii belong to controls; the screen guide keeps square edges. No ornamental gradients, fake metrics, decorative AI imagery, or persistent animation are needed.

Placement guides use blue #0070b8 in the light editor and #5291c4 in the dark editor. Both exceed 3:1 against either standard page background, either request surface and their own grey workspace bed. Keyboard focus rings sit inside the opaque request controls, so their contrast follows the control rather than the surface underneath. Request text, grips and focus use fixed screen pixels; zoom projects world positions, dimensions, grid and guide into the view. The whole workspace is not transformed, avoiding lost native form-control painting after zoom and theme changes. Accepted site previews scale within their own bounded frame. The canvas keeps its own stacking context so request layers stay below editor menus.

Desegnos automatically records each complete generated draft in the project dossier, including its real summary, proposed identity choices, and design feedback. Accepted choices and protected rules remain authoritative. Compatible proposed choices start selected when applying a reviewed site, and users can uncheck them. Draft notes, applied choices, and undone results remain distinguishable. This automatic bookkeeping must preserve ongoing typing, journal durability, undo/redo, and frozen-request validity.

Motion is limited to short control feedback and respects reduced-motion settings. Native dialogs and semantic HTML dialogs retain focus and Escape behavior. Toolbars wrap at narrow window widths while the canvas keeps the full available width. Canvas scrolling remains deliberate and separate from unintended app overflow. Desktop reference pages start at a sensible fit zoom; mobile reference pages fit the available height on open.

New projects explain the create/describe/generate loop and offer Blank website, Use my existing brand, Open project and recent projects. The next screen asks for Web/Mobile, a common resolution or custom size, and a project name. All new pages start light. A compact sun/moon control changes page appearance after creation. Identity import reads a selected Desegnos archive, website folder or ZIP as immutable untrusted evidence, uses the configured AI only after Analyze identity, and offers findings, provenance, uncertainties and reusable logos for approval. Only selected findings and logo bytes become initial project identity; the canvas stays blank.

The supplied identity is preserved under branding/identity, with original logos, Archivo font and OFL notice. The app uses the exact light/dark semantic colours, monochrome outlined wordmarks, Archivo headings and system controls. Dashed lines mark requests and the empty-page choice; solid site content and the static generation seam carry the blank-to-built story. No remote font resources or continuous decorative animation are used. The reference project folder is not an application output.

Export writes a standalone website from included pages with actual styles, scripts, navigation and portable embedded assets. It requires no Desegnos runtime. Core compiles validated project content, storage writes the export safely, and native code owns destination selection and opening the resulting folder. Export has no provider or plugin authority. Plain UI labels describe real behavior: page inclusion is not publishing, and an estimated API budget is not a guaranteed provider billing cap.
