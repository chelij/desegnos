# Desegnos editor design

The editor is one infinite canvas per project, framed by docked panels as in Photoshop. The concept (elements, layers, requests, boundaries, pointers, reference, clashes) is in [CANVAS.md](CANVAS.md); this file covers how the editor looks and behaves. A thin tool strip runs down the left edge. The canvas fills the middle. A right dock holds the Properties panel above the Layers panel. Each panel collapses to an icon strip, Tab hides every panel for a clean canvas, and panel widths and collapsed states are remembered per user. Several projects can be open at once as project tabs, one canvas each; page tabs are gone because every page is a boundary on the canvas. Everything on the canvas is visual; code exists only in exports, where the model becomes ordinary output files and AI can supply missing pointer behaviour.

The tool strip holds Select (V), Request (F), Boundary (B), Pointer (P), Text (T), Shape (R, O, L), Image, Note (N, reference), Insert (Ctrl/Cmd+I, all supported visual elements) and Pan (H), with zoom and Fit at its foot. Every tool and action has a shortcut from the keyboard table in CANVAS.md, using keys common to other design tools. A layer is one element or a group of elements; Properties shows the layer's settings, then its request box, past requests and context. Every tool has its own cursor and a tooltip with its shortcut; a tool with options (Boundary: Page or Screen) shows them as a small flyout from its button. Properties shows the current selection only: boundary name, path, size, kind and appearance; a layer's position, size, fill, stroke, radius, text, image and layout, then its request, history and context; a pointer's comment and clash choices; a reference item's content. Every boundary, including the first, can be deleted; the first included boundary becomes the entry. With nothing selected it shows the project. Layers lists boundaries with their layers, then Reference, then Pointers; selecting a row selects on the canvas and the reverse. There are no other permanent panels. The AI conversation that opens on Generate or Export is a further panel the user can hide. There is no code view: code exists only in an export. Editing stays in the canvas and the panels: no modal dialogs for editing, and Properties replaces the old Edit, Page settings and grid dialogs. Every capability has a visible control; gestures and shortcuts are accelerators, never the only path. One flat menu holds project, export, AI, brief and help commands; anything not built yet appears there disabled as "(coming soon)". The top bar keeps project tabs, a light/dark switch, Import context, Undo/Redo/History, Play, Preview export, Export, Connect AI (only when not connected), AI log and Generate. Copy uses short, ordinary labels. Technical explanations, raw requirements, source, model limits, and diagnostics stay behind Details, Show details or the AI conversation rather than shown by default. Every displayed control performs an implemented operation.

Generate is always visible in an open project and is disabled until there is a request with text. Interpretation is a project setting under Menu → AI style, labelled Flexible / Precise. Fuzzy lets the agent interpret requests and coordinate the composition. Strict follows descriptions, relative placement, and grouping closely while allowing coordinated dimensions and responsive behavior. The setting belongs to the project and frozen generation job; individual requests have no modes. Requests target visual elements and sizes; there is no canvas CSS-editing mode.

Generate freezes a native job and sends it once with the global setting. Generation never blocks the canvas or shifts it. Progress lives in one floating pill at the bottom centre of the canvas ("Designing…" or "Exporting…", elapsed time, Cancel) while only affected requests blur. The AI answers with elements, not code: a validated result appears as editable layers in its request and the pill becomes "Design updated · Undo · Try again". Failures say so in one plain sentence ("Your work is safe") with Try again and Details. Generate also opens the AI conversation panel, showing what was sent (each request, attachments, full instructions) and the reply (live progress, summary, per-request outcomes, suggestions, raw reply, usage). It covers only the latest generation and is not saved. Local edits remain possible and stale-source checks remain authoritative. Details keeps the exact requirements, digest, model details, proposals and attempts behind its Advanced menu. Cancelled or uncertain outcomes explain possible charges in one sentence. A retry requires another explicit paid-send decision and reuses the same frozen request.

Generation feedback stays in the floating pill and the AI conversation. Working states show elapsed time from the current operation or native attempt. Plain status text and a ticking timer communicate activity without invented percentages or looping decoration. The same neutral grey surfaces, readable system type and restrained blue primary action keep this feedback part of the editor. Only stage changes are announced automatically; timer and technical byte updates stay quiet for assistive technology.

AI settings start with the AI provider (the native provider list: OpenAI by key or ChatGPT plan sign-in, Anthropic and Google by key; unimplemented providers show as "coming soon"), then the key. Key storage, model, budget and effort are collapsed under "Where to keep the key" and "Model and spending". Key entry uses a password field cleared on submission; native system storage or session memory holds the key. The editor displays credential status and access-test results, never the secret. Session storage temporarily overrides a system key. Configuration errors remain visible until the native settings operation resolves them.

ChatGPT plan sign-in is available but not advertised. Continue with ChatGPT starts native browser authorization; the editor receives public account status and polls only during a pending sign-in. Saved registrations remain distinct and selectable, with native reconnect, sign-out and storage choices. Manage usage appears beside relevant controls; a plan-limit failure makes Manage usage the primary action. Only native selectable models appear. Review and retry describe the frozen job's own provider and account: plan or credits for ChatGPT, a USD estimate and output cap for keys. Switching settings never redirects a prepared job's provider or authentication.

Optional generation Details presents real source, request coverage, component conflicts, optional identity proposals and advisory design criticism. Automatic Apply accepts the native transaction result; the editor cannot fabricate accepted design state. The canvas draws elements directly; there are no code snapshots and no per-page editor. Play (Shift+Space) makes the selected boundary clickable and runs simple pointers visually. Preview export (Ctrl/Cmd+Enter) exports the selected boundary in the background and runs the real result in place over it in an opaque sandbox until the design changes or Escape. Open in browser serves the last export for a final check in a real browser. No preview receives filesystem, network or editor command privileges.

The active tool decides what a click does. Select: a click selects a layer; This size / All sizes controls choose the linked-size editing scope, and the selection highlights in every size it affects. Double-click enters a group or edits text. Dragging a boundary by its name or empty space moves it and pushes neighbours aside; boundaries never overlap. Request: by default it picks, with an arrow cursor: clicking anything targets it, Shift-click adds or removes targets, and a request box opens beside them; choosing a shape in its flyout (rectangle, ellipse, polygon, freehand) makes dragging draw a request area over whatever it covers instead; Shift+F turns a selected shape's outline into a request area; with something selected, F starts a request on the selection instead. Its targets highlight while it is selected. Rectangle, Ellipse, Line, Text and Image draw or place those elements; inside a box they become its children. Note drops a reference note. Boundary: dragging on empty canvas draws a Page or Screen boundary, which creates its page. Pointer: dragging from a layer or boundary to a target draws a pointer and focuses its comment on the line. Text: clicking a text element edits it in place, committing on Enter or blur and cancelling with Escape. Pan, space+drag, middle-drag and wheel pan; Ctrl/Cmd+wheel and pinch zoom around the pointer. Escape stops Play or Preview export. Ask AI is a labelled selection control and Ctrl/Cmd+K shortcut that opens the element request. A single click selects the topmost layer under the pointer; Enter and Shift+Enter move to its children and parent. A compact action bar follows the selection, prefers its top-left and flips below when that avoids covering surrounding content; it shows the element type and a labelled Ask AI action, with tooltips describing other icons. Hand edits (text, image, style, layout, move, reorder, group, delete) do not call a provider and share durable project Undo/Redo. Dragging a selected element moves it directly; its four corners resize it with the opposite corner anchored. Right-click selects and offers Edit or Generate. Text selection and typing never initiate placement drags. Arrow keys move and resize the selection; Shift moves further. Request text, caret size, focus rings and hit targets remain readable at every zoom level. Positions and sizes are exact on the canvas and become placement intent at export. Files and links can be dropped on a request (or attached in Properties): pictures stay in the project and are inserted after generation, so their bytes never go to the AI; text files and links travel as the request's content. Dropped outside every boundary they become reference items. Shift or Ctrl/Cmd+click selects several items for one Ask AI request or a single Delete. Deleting removes the whole selection in one step and its toast offers Undo.

Use system UI typography for readable native controls, and system monospace for real Markdown and code. Neutral grey chrome in both light and dark themes, as in Photoshop, keeps attention on the work; each base surface has equal red, green and blue channels, and the tool strip and dock sit one step darker than the canvas bed. A sun/moon switch in the top bar flips the editor between light and dark; Menu → Editor theme also offers System. Request surfaces use neutral greys that follow the page appearance. Unfilled requests are see-through so the dots and page show behind them, with a soft halo keeping their text readable; selecting or typing in a request makes it solid. A restrained blue marks the current selection, focus and primary action. Pointers are thin lines with their comment on the line; a clash turns them amber. Errors use text and a clear outline, not colour alone.

The canvas bed is a spreadsheet-like dot grid: one dot at every grid intersection, eight canvas pixels apart, fading out when zoomed far out so it never turns to noise. Snapping, dot visibility and rulers turn on and off independently in Properties with nothing selected. Horizontal and vertical rulers default to pixels relative to the selected boundary, including positions outside it. Alignment guides and a small selection measurement appear during placement. Boundaries keep square edges and their name sits above the top-left corner in small type; small radii belong to controls. No ornamental gradients, fake metrics, decorative AI imagery, or persistent animation are needed.

Placement guides use blue #0070b8 in the light editor and #5291c4 in the dark editor. Both exceed 3:1 against either standard page background, either request surface and their own grey canvas bed. Keyboard focus rings sit inside the opaque controls, so their contrast follows the control rather than the surface underneath. Request text, grips and focus use fixed screen pixels; zoom projects world positions, dimensions, dots and boundaries into the view. Elements move together on one transformed layer; editable native controls are never inside a transformed layer, avoiding lost form-control painting after zoom and theme changes. The canvas keeps its own stacking context so its layers stay below editor menus and panels.

Desegnos automatically records each complete generated draft in the project dossier, including its real summary, proposed identity choices, and design feedback. Accepted choices and protected rules remain authoritative. Identity proposals require deliberate acceptance in the project brief; automatic site application does not silently accept them. Draft notes, applied choices, and undone results remain distinguishable. This automatic bookkeeping must preserve ongoing typing, journal durability, undo/redo, and frozen-request validity.

Motion is limited to short control feedback and respects reduced-motion settings. Native dialogs and semantic HTML dialogs retain focus and Escape behavior. At narrow window widths the dock collapses to icons before the canvas loses width. Canvas scrolling remains deliberate and separate from unintended app overflow. A project opens fitted to all its boundaries; double-clicking a boundary's name zooms to fit that boundary.

Desegnos starts like Excel. By default it opens on a start page laid out like Excel's Home: a narrow left rail (Home, New, Open, and Preferences at its foot) and a content area that uses the window's width. The top section is one row of equal tiles: Blank canvas first, then the templates (Website, App screen, Slide deck, Social image, each creating starter boundaries of common sizes), each tile a large outline preview of its boundaries on the canvas bed with dots, name below. Below it, Recent is a full-width table: name, location, last opened, pin; pinned rows first, row hover shows remove; double click or Enter opens. An empty Recent shows nothing but its header. Open browses for a file. The setting Show start page on launch (Menu → Preferences) turns it off, and Desegnos then opens straight to a blank canvas. Untitled projects are named by template (Untitled website, Untitled app, Untitled deck, Untitled image or Untitled canvas), with numbered suffixes when the name is already open; New (Ctrl/Cmd+N) opens another blank one, and Menu → Home returns to the start page. Open, recent projects and Import website live in the menu. An untitled project asks for its name and location on first save. Unsaved work from a crash is offered back through recovery on launch. All new boundaries start light; appearance changes in Properties. Opening, creating or recovering a project adds a project tab rather than replacing the open project; Close project returns to the previous one. Brand comes in later through Import context: it reads a website address, Desegnos archive, website folder or ZIP as immutable untrusted evidence, uses the configured AI only after Analyze brand, and offers findings, provenance, uncertainties and reusable logos for approval. Only selected findings and logo bytes are merged into the open project's brief as one undoable change; if pages were already generated, Regenerate pages offers to restyle them. A website address pasted on the canvas becomes a reference card. Importing a website converts it into boundaries, layers and elements on the canvas.

The supplied identity is preserved under branding/identity, with original logos, Archivo font and OFL notice. The app uses the exact light/dark semantic colours, monochrome outlined wordmarks, Archivo headings and system controls. Dashed lines mark unfilled requests and empty boundaries; solid site content and the static generation seam carry the blank-to-built story. No remote font resources or continuous decorative animation are used. The reference project folder is not an application output.

Export (Ctrl/Cmd+E) writes a standalone output from included boundaries. For websites and app screens, the exporter compiles HTML/CSS from the resolved element tree and linked sizes, with navigation and packaged assets; missing pointer behaviour may require AI-generated JavaScript. Slides export as PDF and images as PNG or eligible SVG directly. App-screen output is web files, not native packages. Exports require no Desegnos runtime. Core compiles validated project content, storage writes the export safely, and native code owns destination selection and opening the resulting folder. Export has no provider or plugin authority. Plain UI labels describe real behavior: page inclusion is not publishing, and an estimated API budget is not a guaranteed provider billing cap.
