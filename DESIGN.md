# Desegnos editor design

The editor is a full blank workspace with text boxes placed directly where the user wants something. A screen outline is a reference guide inside that workspace. Users can work above, below, and on either side of it. Each page has its own workspace, reached through browser-style tabs. Several projects can be open at once: their page tabs are grouped per project, colour coded, with the project name in small type above each group's first tab. Positions and sizes communicate placement intent; the agent coordinates the actual website layout.

There are no permanent sidebars, docked inspectors, permanent layer panels, or area-caption cards. Two side panels are allowed because the user asks for them and can hide them: the code pane in Split or Code view, and the read-only AI conversation that opens on Generate. Neither is required to build a page. Small floating toolbars and transient popovers are allowed. Layers opens above the canvas tools as a floating popover; its tree selects covered elements and groups without reserving workspace width. Placement is visual first; numeric fields may appear in Edit dialogs for precision. Every capability has a visible control; gestures and shortcuts are accelerators, never the only path. The canvas occupies the workspace. One flat menu holds project, page, preview/code/export, AI, brief and help commands; anything not built yet appears there disabled as "(coming soon)". The top bar keeps the project name, Design/Split/Code, a light/dark switch, Import context, Undo/Redo/History, Preview, Export, Connect AI (only when not connected), AI log and Generate; page tabs sit directly below. Select, Add request, Pan, Layers and zoom live in a compact floating toolbar at the bottom of the canvas; grid settings and the page-check chip sit in the status bar. Copy uses short, ordinary labels. Technical explanations, raw requirements, source, model limits, and diagnostics stay behind Details, Show details or the AI conversation rather than shown by default. Every displayed control performs an implemented operation.

Generate is always visible in an open project and is disabled until a request contains text. Interpretation is a project setting under Menu → AI style, labelled Flexible / Precise. Fuzzy lets the agent interpret requests and coordinate the composition. Strict follows descriptions, relative placement, and grouping closely while allowing coordinated dimensions and responsive behavior. The setting belongs to the project and frozen generation job; individual text boxes have no modes. A request can be marked as a phone fix (Fix on phones), which only allows small-screen CSS to change.

Generate freezes a native job and sends it once with the global setting. Generation never blocks the canvas or shifts it. Progress lives in one floating pill above the canvas tools ("Building your page…", elapsed time, Cancel) while only affected elements blur. A validated result appears directly in the workspace and the pill becomes "Page updated · Undo · Try again". Failures say so in one plain sentence ("Your work is safe") with Try again and Details. Generate also opens the AI conversation: a read-only, hideable right sidebar showing what was sent (each request, attachments, full instructions) and the reply (live progress, summary, per-request outcomes, suggestions, raw reply, usage). It covers only the latest generation and is not saved. Local edits remain possible and stale-source checks remain authoritative. The Details dialog keeps the exact requirements, digest, model details, source code, proposals and attempts behind its Advanced menu. Cancelled or uncertain outcomes explain possible charges in one sentence. A retry requires another explicit paid-send decision and reuses the same frozen request.

Generation feedback stays in the floating pill and the AI conversation; the optional Details dialog retains its sticky header. Working states show elapsed time from the current operation or native attempt. Plain status text and a ticking timer communicate activity without invented percentages or looping decoration. The same neutral grey surfaces, readable system type and restrained blue primary action keep this feedback part of the editor. Only stage changes are announced automatically; timer and technical byte updates stay quiet for assistive technology.

AI settings live in a dialog that starts with the AI provider (the native provider list: OpenAI by key or ChatGPT plan sign-in, Anthropic and Google by key; unimplemented providers show as "coming soon"), then the key. Key storage, model, budget and effort are collapsed under "Where to keep the key" and "Model and spending". Key entry uses a password field cleared on submission; native system storage or session memory holds the key. The editor displays credential status and access-test results, never the secret. Session storage temporarily overrides a system key. Configuration errors remain visible until the native settings operation resolves them.

ChatGPT plan sign-in is available but not advertised. Continue with ChatGPT starts native browser authorization; the editor receives public account status and polls only during a pending sign-in. Saved registrations remain distinct and selectable, with native reconnect, sign-out and storage choices. Manage usage appears beside relevant controls; a plan-limit failure makes Manage usage the primary action. Only native selectable models appear. Review and retry describe the frozen job's own provider and account: plan or credits for ChatGPT, a USD estimate and output cap for keys. Switching settings never redirects a prepared job's provider or authentication.

Optional generation Details presents real source, request coverage, component conflicts, optional identity proposals and advisory design criticism. Automatic Apply accepts the native transaction result; the editor cannot fabricate accepted site state. An opaque sandbox displays registered native preview resources, with page scripts paused until explicitly enabled. Accepted content sits beneath the canvas requests without intercepting authoring input. A separate preview dialog supports interacting with the site. Neither preview receives filesystem, network or editor command privileges.

Double-clicking empty space opens a request. Double-clicking a text element edits its text in place, committing through the existing durable local edit command on Enter or blur and cancelling with Escape. Ask AI is a labelled selection control and Ctrl/Cmd+K shortcut that opens the element request. A single click selects and outlines an actual generated element and dismisses an abandoned empty prompt without opening another one. A floating action bar edits text/link/image/style, replaces, moves, reorders or deletes the selected element locally. Ask AI opens its prompt; these local controls do not call a provider and share durable project Undo/Redo. Dragging a selected element moves it directly; its four corners resize it with the opposite corner anchored. A compact toolbar follows the selection, prefers its top-left and flips below when that avoids covering surrounding content. It shows the element type and a labelled Ask AI action. Tooltips describe other icons. Right-click selects and offers Edit or Generate. Left-drag on empty space pans; Shift+drag draws an area. Ctrl+wheel zooms around the pointer. Selecting another request archives abandoned empty boxes, preserving undo and any scoped decisions. Text selection and typing never initiate placement drags. A selected box exposes small move and resize grips outside the text input. Arrow keys on those grips provide keyboard placement, and Escape from text returns to the move grip. Request text, caret size, focus rings, and grip hit targets remain readable at every zoom level. Text-box dimensions remain authoring hints and do not promise matching generated element bounds. Files and links can be dropped on a request box (or attached with its paperclip): pictures stay in the project and are inserted after generation, so their bytes never go to the AI; text files and links travel as the request's content. Shift or Ctrl/Cmd+click selects several elements for one Ask AI request or a single Delete. The selection toolbar's Style button opens an optional row for colour, fill, text size, spacing and alignment. Deleting asks first unless the user chose "Don't ask again"; Menu → Ask before deleting turns it back on, and Undo always works.

Use system UI typography for readable native controls, and system monospace for real Markdown and code. The user requested grey like Photoshop. Neutral grey chrome in both light and dark themes keeps attention on the website; each base surface has equal red, green and blue channels. A sun/moon switch in the top bar flips the editor between light and dark; Menu → Editor theme also offers System. This palette direction does not add Photoshop panels or change Desegnos's canvas layout. Text-box surfaces use neutral greys that follow the page appearance. Unselected request boxes are see-through so the grid and page show behind them, with a soft halo keeping their text readable; selecting or typing in a box makes it solid. A restrained blue marks the current selection, focus and primary action. Errors use text and a clear outline, not color alone.

The workspace grid starts on, with eight-pixel spacing. Users can choose spacing in pixels or percentages of the screen guide, and turn grid visibility, snapping, or rulers on and off independently. Horizontal and vertical rulers default to pixels relative to the guide, including positions outside it. Percent is available in settings independently of grid spacing units. Alignment guides and a small selection measurement appear during placement. The guide and accepted preview have separate extents so a long site can extend below its reference screen. Small radii belong to controls; the screen guide keeps square edges. No ornamental gradients, fake metrics, decorative AI imagery, or persistent animation are needed.

Placement guides use blue #0070b8 in the light editor and #5291c4 in the dark editor. Both exceed 3:1 against either standard page background, either request surface and their own grey workspace bed. Keyboard focus rings sit inside the opaque request controls, so their contrast follows the control rather than the surface underneath. Request text, grips and focus use fixed screen pixels; zoom projects world positions, dimensions, grid and guide into the view. The whole workspace is not transformed, avoiding lost native form-control painting after zoom and theme changes. Accepted site previews scale within their own bounded frame. The canvas keeps its own stacking context so request layers stay below editor menus.

Desegnos automatically records each complete generated draft in the project dossier, including its real summary, proposed identity choices, and design feedback. Accepted choices and protected rules remain authoritative. Identity proposals require deliberate acceptance in the project brief; automatic site application does not silently accept them. Draft notes, applied choices, and undone results remain distinguishable. This automatic bookkeeping must preserve ongoing typing, journal durability, undo/redo, and frozen-request validity.

Motion is limited to short control feedback and respects reduced-motion settings. Native dialogs and semantic HTML dialogs retain focus and Escape behavior. Toolbars wrap at narrow window widths while the canvas keeps the full available width. Canvas scrolling remains deliberate and separate from unintended app overflow. Desktop reference pages start at a sensible fit zoom; mobile reference pages fit the available height on open.

New projects always start blank: the start screen explains the create/describe/generate loop and offers Blank website, Open project and recent projects. The next screen asks for Web/Mobile, a common resolution or custom size, and a project name. All new pages start light; page appearance changes in Page settings. Opening, creating or recovering a project adds a tab group rather than replacing the open project; Close project returns to the previous one. Brand comes in later through Import context: it reads a website address, Desegnos archive, website folder or ZIP as immutable untrusted evidence, uses the configured AI only after Analyze brand, and offers findings, provenance, uncertainties and reusable logos for approval. Only selected findings and logo bytes are merged into the open project's brief as one undoable change; if pages were already generated, Regenerate pages offers to restyle them.

The supplied identity is preserved under branding/identity, with original logos, Archivo font and OFL notice. The app uses the exact light/dark semantic colours, monochrome outlined wordmarks, Archivo headings and system controls. Dashed lines mark requests and the empty-page choice; solid site content and the static generation seam carry the blank-to-built story. No remote font resources or continuous decorative animation are used. The reference project folder is not an application output.

Export writes a standalone website from included pages with actual styles, scripts, navigation and portable embedded assets. It requires no Desegnos runtime. Core compiles validated project content, storage writes the export safely, and native code owns destination selection and opening the resulting folder. Export has no provider or plugin authority. Plain UI labels describe real behavior: page inclusion is not publishing, and an estimated API budget is not a guaranteed provider billing cap.
