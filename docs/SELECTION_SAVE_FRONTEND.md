# Stable selection and safe save frontend

Implemented against `SELECTION_AND_SAVE_SPEC.md` and the native contracts from the stable-target and safe-save branches. No sidebar, network generation or production app launch. The source editor uses the explicitly required CodeMirror 6 packages reviewed in `CODEMIRROR_DEPENDENCY_REVIEW.json`.

- Canvas selections use editor IDs. A positional selector and source fingerprint remain supported only for legacy targets. Shift, Control or Command click toggles a selection; contained selections reduce to their outer element. One request can target up to eight elements, with a union placement rectangle.
- Multiple selections expose Ask AI and Delete. Delete calls one atomic native command and therefore takes one project Undo. Multi-element drag, resize, cut, copy and arrange remain unavailable; their single-element keyboard actions cannot silently modify just one of several selected elements.
- Pending request bounds refresh through `refresh_element_target_bounds`. Existence is checked independently of visible bounds: hiding an element does not make its request stale. A missing ID shows “This element was removed”, with Pick again and Remove request. Retargeting preserves the request ID, prompt and linked brief rules in one command. AI root deletion needs the explicit request context-menu choice “Allow AI to remove selected items”.
- Page check and code navigation carry IDs and an expected page ID. A delayed page switch cannot select a matching positional path from the previous page. A failed lookup cannot turn an element-specific fix into an unrelated page-area request. Fragment HTML uses the exported page name as its title; only an explicitly empty title is flagged.
- Code view removes editor attributes from visible HTML by default. The native source map is projected into visible UTF-16 positions. The attributes remain tracked outside the textarea and are restored on save, using exact CodeMirror transactions so inserting similar tags does not move existing IDs to new elements. CodeMirror text undo/redo restores metadata through its inverted-effects history. Native IDs assigned on save rebase through typing that happened while the save was running. Each language keeps an independent local text history. The Show editor attributes toggle is disabled while an HTML draft is unsaved. Invalid draft text remains in place with projected error positions.
- Browsing or dropping onto an image placeholder preserves authored safe attributes, including width and height, while replacing the placeholder and clearing old provenance. This uses the native validator for the final HTML.
- Save uses `save_project_checked` and `resolve_save_conflict`, including repeated conflicts if a disk file changes again. Changed-file conflicts default to Save as copy. Replacing another project through Save as defaults to Cancel. A file belonging to a different project during ordinary Save can only be copied to a new name. Revision and file hashes are only under Show details. Cancelling a choice or the file dialog keeps the recovery journal.
- Recovery rows show the saved file name and relative edit time, with the full path on hover.

## CodeMirror 6 implementation

The native source validator remains authoritative. The editor keeps rejected drafts, projects diagnostics into visible HTML coordinates, refuses stale bases, and returns exact applied source from `saveSource` so native ID assignment can rebase safely. The code pane never formats authored HTML/CSS behind the user's back. CodeMirror supplies syntax parsers, line numbers, multi-cursor editing, keyboard editing, selection, search, and text-local history. Its bundle loads only when Split/Code opens.

The editor uses nine exact-pinned direct packages and 12 transitive packages, all MIT licensed, with full upstream notices in `CODEMIRROR_NOTICES.md`. The dependency review records provenance, every resolved integrity hash, license text and hash, absence of install lifecycle scripts, and the production `pnpm audit` result (zero reported advisories on 2026-10-20). The archived GitHub CodeMirror repositories link to the active maintainer-hosted repositories; the review uses the official npm metadata and distributed API documentation rather than treating the archive as abandonment.

Native test adaptation: the source surface is `.cm-content[role="textbox"][aria-label="HTML code"]` (or CSS / JavaScript) instead of a textarea. Fill it through normal select-all and typing/paste input; a `.value` setter is not an editor operation. CodeMirror's `.cm-line` elements are virtualized; read native source or CodeMirror state when testing the entire document. Selection/search/error line decorations retain `.code-line.selected`, `.code-line.match` and `.code-line.error` on rendered `.cm-line` elements. Source editor handles have `data-testid="source-editor-html"`, `source-editor-css` and `source-editor-javascript`.

## Code draft lifecycle

`CodePaneHandle.synchronize()` clears delayed saves, waits in-flight and queued edits, and flushes all language files before navigation. It rejects with plain text while an invalid, conflicting or unsaved draft remains, reveals the affected file, and keeps the pane and text present. It allows three flush passes and a 15-second deadline; a timeout blocks the transition and does not cancel an already accepted native edit. A confirmed native save updates the draft base even before React paints the returned source.

App transitions now synchronize both code and canvas before Save, Save as, open/create/recovery replacement, close, export, generation prepare/apply, project undo/redo, page change/removal, and Design/Split/Code change. The source-edit command itself synchronizes only the canvas so it cannot recursively invoke its own code flush. Ctrl/Cmd+S inside CodeMirror invokes project Save through the same barrier. CodeMirror owns its text Undo/Redo; the Linux native-input fallback skips CodeMirror and already handled keyboard events.

Rejected drafts expose **Discard code changes**, which discards only that code file, preserves other drafts, and does not rerun a rejected save on blur. Storage/other transient source errors also expose Try saving again. Seven lifecycle regressions cover all-file flushing, waiting for an in-flight edit, invalid/conflict/error blocking without text loss, bounded retries during continued typing, and timeouts that keep the page open. Native transition and immediate-save acceptance is coordinated by the parent task.

## React echo and text history safeguard

CodeMirror owns local text state. A delayed React acknowledgement of an earlier keystroke can update metadata only if its text matches CodeMirror's current document; it cannot replace newer text or reset local history. Document replacement is explicit for authoritative native source (only when no local draft exists), Discard code changes, and the editor-attribute representation toggle. Nine actual CodeMirror state regressions now include stale echoes and every ordinary metadata/read-only/line/search update interleaved with fast typing. The interleaved effects preserve one group in the controlled timestamp test. Native typing may still form several ordinary undo groups; one Undo must change only code, and Redo must restore the exact undone text.
