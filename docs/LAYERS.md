# Local layers and clipboard

Selecting a website element or request shows four icon buttons at its top-left: Layers, Copy, Cut and Delete. Layers opens beside that bar and stays within the workspace. It also opens from the floating canvas tools or Menu → View → Layers when nothing is selected. Right-click an element, request, layer row or empty canvas for relevant editing, arrangement, clipboard, history and view actions. F2 and the right-click Edit action retain local editing; Ask AI is in the right-click menu or Ctrl/Cmd+K. It occupies no reserved workspace width. Website elements appear in their existing parent groups, front first; Requests lists pending prompts separately. A visible child remains reachable when its wrapper uses `display: contents`, has no dimensions, or hides itself while the child remains visible. Images and graphics use their available accessible names. SVG graphics are selected as a unit in the tree.

Select a covered item in Layers to outline it on the canvas. Bring forward / Send backward move it one level within its existing parent. Bring to front / Send to back move it to the ends. Select a group to arrange its contents together. These operations change stacking, preserve DOM reading order and verify the measured layout before committing. The planner changes the selected element's inline style; it never renumbers unrelated website siblings or turns a negative background decoration into a foreground item. If existing CSS painting or integer stacking levels cannot express the requested order safely, the editor reports that and asks for the containing group. It does not silently change layout or reparent content.

Pending requests use stable `zIndex` ordering with array order as the tie-breaker. Their IDs, dimensions, text, completed history and generation coverage remain intact. Selected request outlines and handles sit above the request surfaces; focus does not secretly bring an opaque request to the front.

Copy / Cut / Paste work through the system clipboard. Cut completes a validated clipboard write before a revision-checked durable deletion; failure or a changed project preserves the original. It is one undoable edit. Ctrl/Cmd+C, Ctrl/Cmd+X and Ctrl/Cmd+V apply to the selected layer outside text inputs. Ordinary text selection retains the native clipboard shortcuts. Ctrl/Cmd+] / [ arrange one level; Shift moves to front/back. Menu → Edit and the Layers toolbar expose the same commands visibly.

Copying does not change the project. Pasting creates one undoable transaction, selects the result and offsets it by 24 CSS pixels. Website content is inserted after the selected sibling or into the page body. Requests get a new identity and no inherited binding to a former generated element. Website IDs are renewed, and internal labels, links, ARIA references and SVG/CSS fragment references follow those new IDs. Undo/Redo, Save/Open, the journal and portable export use the ordinary project/source transactions.

A copied website layer includes its static markup, native controls, image/resource references, current computed appearance, `::before`, `::after` and list marker styling. Scoped decoration CSS stays with the pasted project, including when pasted onto a different page. It does not import the source page's entire stylesheet or execute source programs. Existing runtime JavaScript listener closures are not cloned; copied classes/markup may still participate in the destination page's existing scripts. Subtrees containing embedded scripts, stylesheets, frames or objects fail with an explicit instruction to choose a smaller visual layer. This is a visual layer copy, not the future reusable-component or responsive-style library.

## Boundaries

The React editor reads the trusted scriptless preview to identify current nodes and measure style/layout. Native commands verify project identity and revision. `desegnos-core` validates targets, clipboard format, source hashes, markup/context, uniqueness and style bounds, then creates the complete transaction. `desegnos-storage` persists through the existing archive/journal paths. No provider request, key access or executable product plugin is involved.

The system adapter uses the official [Tauri clipboard plugin](https://v2.tauri.app/plugin/clipboard/), pinned to `tauri-plugin-clipboard-manager` 2.5.0 (MIT OR Apache-2.0). Its existing platform adapters support the desktop clipboard; it adds no JavaScript dependency. The lockfile adds 35 transitive packages without upgrading existing resolutions. Image support comes from the official adapter's platform feature set, although this feature transfers typed UTF-8 layer packets only. No general clipboard permission is granted to the frontend or preview. Reads occur only on Paste, writes only on Copy or Cut, on blocking workers outside the workspace lock. There is no startup read, clipboard polling or clipboard clearing.

Clipboard JSON is bounded to 8 MiB, markup to 1 MiB, styled elements to 512 and nesting to 64. Each regular/pseudo style is bounded to 65,536 bytes, with a 2 MiB combined style budget. The OS adapter returns a complete string before its byte check; it cannot cap the operating system's transfer allocation. Unsupported or oversized packets fail without truncation or a partial project change. These are clipboard/source support bounds, separate from the uncapped logical request canvas.

The remaining organizer features—rename, group/ungroup, compatible reparenting, lock and hide—retain their release-plan scope and are not exposed as inert controls.
