# Standalone desktop audit

Scope: runtime code in `src/`, `src-tauri/src/`, and `crates/*/src`, excluding test modules/fixtures. Findings below reference this change's source lines. Status is included in the fix column. No builds, tests, native launches, or live tool probes were run during the audit; verification was source review, Rust formatting and `git diff --check`. Image generation/settings and recovery-dismiss code were inspected where relevant but left unchanged.

## Release and negative checks

Source inspection found no runtime `localhost:1420` fallback in the audited trees. Tauri's development URL is confined to `src-tauri/tauri.conf.json` build.devUrl; packaged assets use frontendDist when custom-protocol is enabled, and reload recreates the configured editor window; this audit added a release compile error when Tauri is still in development mode. Native automation is rejected in release by `src-tauri/src/main.rs:3`; `crates/desegnos-ai/src/lib.rs:1` independently rejects test-support in release. Loopback provider constructors, memory vaults, and fixture image/website hosts are test/test-support gated; the desktop native-tests feature enables that guarded dependency. The private foreign-provider HTTP constructor receives production HTTPS hosts from its only runtime caller. Internal preview custom-protocol .localhost names and .invalid URL-resolution bases are routing/origin identifiers, not development-server fallbacks. The public website fetch API now also rejects explicit fixture origins outside test/test-support builds. Source review of the installed Tauri 2.12.4 / tauri-codegen 2.7.3 confirmed that custom-protocol, rather than debug_assertions, selects embedded assets; no build was run to validate packaging.

No runtime npm/pnpm/yarn/hugo/node commands exist outside website rebuilding. Linux graphics startup re-executes the current app's absolute executable; its optional `/sys/module/nvidia` probe is Linux-gated and absence disables only that workaround. Linux-specific WebKit context-menu/preview registration code has no Linux binary dependency on Windows/macOS, but visual/menu parity still needs platform QA. Archivo is shipped as WOFF2; other named UI fonts have generic system-ui/monospace fallbacks and are not installation requirements. No runtime writes target the executable/resource directory. Source-only developer home paths found inside tests were excluded from findings.

## Windows developer tooling follow-up (2026-10-22)

- FIXED: `scripts/build-release.mjs` replaces the release shell logic; `npm run release:local` works without Bash, `stat`, or mise. - FIXED: `scripts/tauri.mjs` maps `CI=1` to `CI=true` in the Tauri child environment because the CLI's boolean parser rejects `1`. Other CI values remain unchanged.
- FIXED: `scripts/launch-paths.mjs` compares resolved link destinations with Windows case folding, accepts absolute or relative targets, and restores Windows launch aliases using verified copies without requiring symlink privileges. The tests use platform executable names and assert copies on Windows; only symlink-specific tests skip there, with an explicit Developer Mode/elevation reason.
