# Native editor checks

This harness drives the real Tauri editor through the embedded WebDriver server in `tauri-plugin-wdio-webdriver`. It renders in WebKitGTK, sends operating-system pointer and keyboard events through the system X11/XTEST libraries, calls actual Rust commands, and verifies that a fresh process recovers acknowledged edits after SIGKILL. It does not mock `invoke` or replace the project model.

Run `pnpm test:native` or `node scripts/native-test.mjs` from the repository. The runner builds the explicit `native-tests` feature with `src-tauri/tauri.test.conf.json` into `target/native-tests`, then starts a private Xvfb display through `~/.local/bin/xvfb-run -d`. It creates its own session bus, profile, data directory, cache, runtime directory and free localhost port. Before interaction, it verifies that the display number is at least 90, differs from the original desktop display, and was inherited by the native app. It checks the process owner and mapped X11 window's published PID before every physical input request. Only its own test window is resized for the minimum-width check. Existing desktop X11 resources and an initially available desktop connection are checked after cleanup.

To use a previously built test binary, run `node scripts/native-test.mjs --skip-build --binary /absolute/path/to/desegni`. That binary must have been built with both the explicit feature and test configuration. A default production binary has no WebDriver server and will fail readiness.

## Integrated test build

The repository already declares the optional Rust dependency `tauri-plugin-wdio-webdriver = "=1.5.0"` and enables it only through the `native-tests` feature. The native entry point registers the driver only under that feature and has a compile-time error that rejects `native-tests` in release builds. The normal production configuration and editor capability do not enable the driver or global test API.

The explicitly selected `tauri.test.conf.json` adds the documented global Tauri API and the embedded driver's empty IPC permission set. No npm testing dependency, `wdio.conf`, application-side test shim or `tauri-plugin-wdio` is used by this direct W3C client. `x11-input.py` uses Python's standard library and installed system `libX11`/`libXtst`; it fails explicitly if either library or XTEST is unavailable. The helper is GPL-3.0-only like this repository. It loads these system libraries rather than copying their implementations; their installed X.Org/Open Group/UniSoft license notices were reviewed. No product dependency was added for physical input.

The embedded server binds to `127.0.0.1`, reads `TAURI_WEBDRIVER_PORT` and supports the W3C routes used here. Session creation waits for a native window, so the runner also waits for the mounted application through the direct page-source endpoint before scripted interaction. This avoids a first-navigation race in the driver's synchronous script result polling. Its DELETE session handler only removes the driver session's in-memory map entry; the crash path bypasses that command entirely. On a virtual X server without a window manager, the driver's outer window size can report zero, so the minimum-width check restores the directly observed webview size. These testing dependencies are separate from Desegnos's product plugin framework. The test feature also propagates the provider's release-guarded loopback support. Only that feature reads DESEGNI_NATIVE_TEST_OPENAI_ENDPOINT; it accepts literal loopback, an explicit port and /v1. Product builds have the fixed OpenAI HTTPS endpoint. Native test builds forward WebKit console diagnostics so expected policy denials can be distinguished from loading failures; they never grant the preview additional permissions.
