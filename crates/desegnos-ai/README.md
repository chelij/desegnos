# Desegnos AI providers

This crate accepts frozen requirements and a strict core output schema. It sends one bounded provider request, parses its stream, and returns text, response identity and reported usage. It cannot apply a candidate, edit a project, install components, register a preview or write model-selected files. The native coordinator must persist intent before calling `generate`, preserve attempts, validate returned text with core, and obtain explicit authorization for retries and application.

Generation and identity builders validate task content before choosing a provider wire format. OpenAI encodes documents as attachments; Anthropic and Google encode their text directly. Provider settings, schemas, image validation, final request-size limits and budget checks remain enforced before submission.

## Integration API

All serializable view fields use camelCase.

- `ProviderSettings { model, max_output_tokens, reasoning_effort, spending_limit_usd, image_generation, pricing?, endpoint?, local_authentication? }`; `Default` selects GPT-6.1 Sol, medium, 32768 tokens and USD 2. Validation checks safe identifiers, limits, finite allowances and optional model-bound price ceilings. Native save and submission additionally require membership in the connected account catalogue.
- `model_catalogue() -> Vec<ModelInfo>` exposes `id`, `name`, `inputUsdPerMillion`, `outputUsdPerMillion`, `verifiedAt`, `sourceUrl`, `reasoningEfforts`, `contextWindowTokens`, `maxOutputTokens`, `longContextInputUsdPerMillion` and `longContextOutputUsdPerMillion`. The output cap is Desegnos's cap.
- `estimate_cost(&RequirementsSnapshot, GenerationMode, &Value schema, &ProviderSettings) -> Result<CostEstimate>` shares the generation request's complete validation. `CostEstimate` exposes `estimateUsd`, `inputTokenUpperBound` and `verifiedAt`.
- `CredentialManager::new()`, `status() -> CredentialInfo`, `set_key(String, CredentialStorage) -> Result<CredentialInfo>`, `remove_key() -> Result<CredentialInfo>` and `key() -> Result<ApiKey>`. `CredentialStorage` is `System` or `Session`. `CredentialInfo` contains only configured status, `system | session | none`, masked identifier and a safe vault error. The opaque, cloneable `ApiKey` has no serialization or public secret accessor; its debug representation is redacted.
- `OpenAiClient::new() -> Result<Self>` creates a cloneable client. `generate(&RequirementsSnapshot, GenerationMode, &Value schema, &ProviderSettings, &ApiKey, &CancellationToken, impl Fn(ProviderProgress) + Send + Sync) -> Result<ProviderResponse>` is async. `ProviderResponse` has `text`, `response_id` and optional `TokenUsage { input_tokens, output_tokens, total_tokens }`.
- `test_model_access(&ProviderSettings, &ApiKey, &CancellationToken) -> Result<()>` is async and performs an authenticated model GET without generating content. It verifies the returned model ID and object type. Successful model retrieval establishes access to that model endpoint; a future generation can still be rejected by account permissions or limits.
- `CancellationToken::new()`, `cancel()` and `is_cancelled()`; the token is cloneable. `ProviderProgress { received_bytes, response_id }` contains response wire bytes and a checked ID, never partial model text or credentials. Keep the synchronous progress callback short and hand durable updates to the coordinator's queue.

Keyring operations are synchronous. Invoke credential methods on a blocking worker, serialize operations on the same manager, and keep them off the native event loop. The manager accesses only its own `io.desegnos.openai` / `api-key` entry. Linux uses Secret Service, macOS Keychain, and Windows Credential Manager. It never automatically falls back to plaintext or session storage.

Session-only storage is a temporary override: an existing saved system key remains until Remove succeeds. Quitting discards the memory override, after which the saved key is available again. Failed system writes or deletions preserve the accepted in-process credential state. Key buffers are zeroized when their last Rust handle is dropped; the HTTP library necessarily holds its own sensitive authorization header during a request. Key input checks only nonempty bounded header-safe ASCII and does not guess provider key prefixes.

`ProviderError` contains `kind`, `outcome`, optional checked `response_id` and optional usage. `Display` and `message()` return fixed safe text. Provider error bodies, refusal text, low-level transport errors and vault errors are never forwarded verbatim. Response IDs and candidate text containing the submitted key are rejected. `SubmissionOutcome` is `NotSubmitted`, `Rejected`, `Unknown` or `Received`. `Unknown` means the coordinator must retain billing uncertainty and must not automatically retry. Cancellation after submission can also leave a charge. Successful HTTP completion does not authorize applying source.

## ChatGPT authentication

`AuthenticationMethod` is `apiKey | chatgpt`, defaulting to API key for existing records. `estimate_for_auth` and `generate_for_auth` preserve exact requirements, schema and global mode. Existing API-key entry points remain wrappers with unchanged behavior. Plan requests omit unsupported `max_output_tokens` and service-tier fields, ignore unused API monetary allowances, and reserve the verified 128,000-token model output capacity. The API cap remains 32,768. The plan USD estimate field is unused; it must never be presented as free usage or a billing guarantee.

`ChatgptManager` implements OpenAI's [open-source sign-in protocol](https://developers.openai.com/siwc/token-sharing-open-source/sign-in): a literal loopback callback, state/nonce/S256 PKCE, dynamic first registration, stable issued-client/host mappings, JWKS signature/issuer/audience/expiry verification and explicit direct-plan scope. It owns private metadata and credential records, never project authority. Public views contain account labels, identity/status, models, errors and secure-storage repair status; opaque authorization URLs are native-only and debug-redacted. `bearer(account_id, cancellation)` never changes accounts or billing methods.

Refresh serializes across processes and replaces complete access/refresh/ID-token bundles. A validated rotation whose secure write fails stays privately in memory; generation waits for `retry_secure_storage(account_id)`, which saves that exact replacement without HTTP. A durable non-secret fence prevents other processes from replaying the consumed token. Keep the owning process open for repair; otherwise reconnect the saved registration. A successful session-only reconnect retires its owned older system credential. Sign-out stops matching pending authorization and inference, attempts discovery-based revocation with the newest token, clears local access and retains the registration. Remote failure is reported honestly.

`list_chatgpt_models` performs authenticated `GET /models`, reads server `slug`/`display_name`, keeps `visibility: list` in server order and enforces bounds. ChatGPT selection uses this account catalogue directly, without the API pricing allowlist. Opening AI settings or pressing Refresh models explicitly fetches it again; ordinary status polling stays network-free. Discovery retains advertised `supported_reasoning_levels`, `context_window` and optional `max_output_tokens`. Reasoning identifiers are bounded strings, so new model IDs and effort levels do not need code changes. Omitted reasoning metadata retains the existing low/medium/high subset; an explicitly empty list omits the reasoning parameter. Missing context metadata retains the application limit; native generation, identity and export check advertised limits when provided, alongside existing application byte/context/output limits. Provider capability rejections remain explicit failures, never automatic retries or billing fallbacks. API-key selection also uses account discovery; its estimates use verified prices when known and explicit model-bound price ceilings otherwise.

Native save and submission validate the selected model and effort against the active connected account, including plan permission and secure-storage status. New models do not inherit Sol's API prices or catalogue verification label. `ProviderError` retains authentication, HTTP status and bounded safe code/parameter/request ID. A terminal failed SSE event after partial text never returns a candidate.

`ChatgptManager::initialize` performs local initialization without HTTP. Optional metadata damage must remain visible without preventing ordinary authoring. Native code opens only the manager's trusted authorization URL or the fixed ChatGPT usage destination through the maintained `open` launcher also used by Tauri. See [CHATGPT_CONTRACT.md](../../docs/CHATGPT_CONTRACT.md) for the full native/editor API and verification boundary.

## API model discovery

OpenAI API-key, Anthropic, Google, OpenRouter and Local connections discover models from their configured connection, without model-name allowlists. The shared native discovery module retains provider order and names, follows Anthropic `after_id` and Google `pageToken` pagination, and reads advertised reasoning/input/output metadata. Google embedding-only models are excluded because they cannot run generation. Unadvertised reasoning for an unknown model uses the provider default by omitting the optional parameter. A provider may still reject a model's request capabilities; errors never cause a retry or another billing route. OpenRouter uses the account-filtered `/models/user` endpoint with `limit`/`offset` pagination. Local uses OpenAI-compatible `/models`. Both generate through streaming `/chat/completions` with strict JSON-schema output, exact model IDs and optional reasoning; tool calls, refusals, incomplete answers and missing terminal markers fail explicitly. Web search and image generation are not advertised for these two providers. Neither adapter installs or starts a local server.

Discovery is read-only and uses the existing hardened HTTP clients and provider authentication headers. Each operation has a 30-second deadline, at most 32 pages, 1 MiB per page and 4096 model records. Duplicate IDs/cursors, unsafe IDs/names, credential echoes, invalid limits and malformed responses fail explicitly. Caches bind provider, credential fingerprint and (for Local) the normalized server URL; another key's list is never displayed or used. Opening settings, switching a provider, connecting a key or pressing Refresh models refreshes discovery. Ordinary status reads remain network-free. Save, generation, identity and export check account membership, supported reasoning and advertised token bounds before submission.

OpenAI, Anthropic and Google model endpoints do not supply prices. Verified catalogue entries supply known rates; newly discovered models set `pricingRequired` and require input/output ceilings in USD per million tokens before saving or generating. `pricing` is optional for existing settings and is omitted from their serialized form when absent. It binds both ceilings to the selected model ID, permits explicit zero for free usage, and rejects negative/non-finite rates or a different model ID. Unknown models never inherit another model's rates. Estimates and the existing budget check apply the entered ceilings, which are user-supplied estimates rather than provider billing caps. OpenRouter quotes prefill model-bound input/output prices (converted from USD per token), plus per-request and per-image fees; current discovered quotes must fit the saved ceilings. Invalid or missing quotes require manual ceilings. Estimates include these fees. Local defaults to editable zero prices for on-device inference. This needs no dependency or code update for new model IDs.

Local defaults to `http://127.0.0.1:11434/v1`. AI settings lets users connect another loopback HTTP/HTTPS address ending in `/v1`, including IPv6 loopback; `localhost` is normalized to `127.0.0.1`. Userinfo, queries, fragments and non-loopback destinations are rejected. Settings freeze the server address and key mode for each job. Anonymous mode never reads secure storage or sends an Authorization header. Adding a key explicitly enables authentication; removing it or choosing “Use without a key” restores anonymous mode. A configured key failure never silently sends an anonymous request. Existing provider settings omit these optional fields unless used.

Protocol references checked 2026-10-31: [OpenAI List models](https://developers.openai.com/api/reference/resources/models/methods/list), [Anthropic List Models](https://platform.claude.com/docs/en/api/http/models/list), [Google Models](https://ai.google.dev/api/models), [OpenRouter account model lists](https://openrouter.ai/docs/api/api-reference/models/list-models-filtered-by-user-provider-preferences-privacy-settings-and-guardrails), [OpenRouter chat completions](https://openrouter.ai/docs/api/api-reference/chat/create-a-chat-completion), and [Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility). Discovery alone does not claim compatibility with every possible future generation protocol. Run `npm run test:ai-models` for isolated headless settings checks; Rust provider tests cover loopback discovery and generation.

## Identity analysis

`OpenAiClient::analyze_identity_for_auth(authentication, &RequirementsSnapshot, &Value schema, &ProviderSettings, &ApiKey, &CancellationToken, &[IdentityImage], progress)` sends a distinct identity-analysis request through the same cancellation, no-retry transport and completed-stream correlation. `estimate_identity_for_auth(authentication, snapshot, schema, settings, images)` performs identical preflight validation. The caller owns source collection, informed submission, identity-specific candidate validation, review and application. This crate neither reads imported files nor applies extracted decisions.

The frozen Markdown is attached as `IDENTITY-SOURCES.md`; it need not contain a generation-mode section or requested page areas. Nonempty Markdown, digest, nonnil job/project IDs and a strict object schema with required string `jobId` and `requirementsSha256` are mandatory. Those properties are bound to singleton enums without mutating the caller's schema. The separate metadata has `purpose: identityAnalysis`; the strict schema name is `desegnos_identity_candidate`. Instructions treat imported text, code, documents, image content and comments as untrusted evidence; ask for source references, uncertainty and conflicts; and prohibit website generation, code execution, tool use and credential disclosure. Native code must validate all identity fields and source references before showing or applying a result.

`IdentityImage { data_uri: String }` accepts only canonical Base64 local PNG, JPEG and WebP data URIs with matching format signatures. SVG stays as source text in the Markdown; GIF is omitted rather than accepting animation. The transport does not decode or execute images. Use at most four images, each full URI at most 256 KiB and all URIs together at most 512 KiB. Match their 1-based input order to source references in the Markdown. Each image is sent as Responses `input_image` with `detail: high`; no URL fetching or file-upload endpoint is used. See OpenAI's [Responses input-image definition](https://developers.openai.com/api/reference/resources/responses/methods/create) and [supported vision inputs](https://developers.openai.com/api/docs/guides/images-vision), checked 2026-10-19.

Preflight counts every serialized byte and additionally reserves 65,536 input tokens per image, independent of compressed size, before enforcing context and API spending limits. This deliberately exceeds the documented 30,000-patch rejection threshold with token-multiplier headroom; re-evaluate the reserve when the verified model changes. ChatGPT requests retain the model output reservation and never switch to an API key or another route on capability, quota or transport failure. Returned text, response identity, usage and safe errors follow the existing generation contract; generic job/digest checks do not replace native validation of the identity schema.

## Wire and bounds

Production has one fixed base URL, `https://api.openai.com/v1`, with certificate verification and HTTPS-only transport. The client disables redirects, automatic retries, proxies, HTTP referers, TLS key logging and response decompression. It sends `store: false`, `service_tier: "default"` (standard processing), `stream: true`, no tools and a strict `text.format` schema. Generation has a five-minute deadline; the non-generation access check has a 30-second deadline.

`REQUIREMENTS.md` is attached as `input_file` using `data:text/markdown;base64,` plus Base64 of the exact UTF-8 bytes. A separate `input_text` JSON record carries the job ID, digest and global mode. The adapter verifies the Markdown hash and its single generation-setting block. It does not summarize, normalize newlines, change Unicode or truncate input. OpenAI documents Markdown support and inline Base64 file input in its [file-input guide](https://developers.openai.com/api/docs/guides/file-inputs).

The application accepts at most 8 MiB of requirements, 256 KiB of schema, 16 MiB of serialized request, 32 MiB of response stream and 8 MiB of candidate text. The context check counts every serialized wire byte as a token and adds 4096 tokens of framing headroom before reserving output tokens. This deliberately overestimates the Base64 attachment and can reject a request that a tokenizer would fit. For verified OpenAI models it uses the selected model's long-context input price with 25% cache-write headroom and long-context output price; for unknown models it uses the explicitly entered price ceilings, rounds upward to cents and compares the result to the configured allowance before connecting. This is a conservative local estimate, not a guaranteed billing cap or tokenizer result. Pricing changes, framing and explicit retries can affect actual charges.

The stream decoder supports LF, CRLF, CR and multiline SSE data across arbitrary HTTP chunks, including split UTF-8 sequences. A completed response must agree with collected text, have consistent usage and identity, contain valid JSON, and bind to the frozen job and digest. Refusal, incomplete, truncated, malformed, over-limit and inconsistent output cannot become a successful provider result. Full candidate/schema/domain validation remains core's responsibility. OpenAI describes [streaming lifecycle events](https://developers.openai.com/api/docs/guides/streaming-responses) and [structured-output refusals/incomplete handling](https://developers.openai.com/api/docs/guides/structured-outputs); the access check uses [Retrieve model](https://developers.openai.com/api/reference/resources/models/methods/retrieve).

## Verified catalogue and dependencies

The official pages for [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), [GPT-6.1 Terra](https://developers.openai.com/api/docs/models/gpt-6.1-terra) and [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) were fetched on 2026-10-31. All support text/image input, structured output, web search, low/medium/high reasoning, a 1,050,000-token context and 128,000 model output tokens. Standard input/output prices per million are Sol USD 2/10, Astra USD 10/50, Terra USD 1/5 and Luna USD 0.10/0.50. Above 272K input, input rates double and output rates multiply by 1.5. Desegnos exposes low, medium and high and caps API output at 32768. The catalogue verification date is explicit and account access is checked separately.

## Verification

Run `node scripts/cargo.mjs test -p desegnos-ai --all-features` and `node scripts/cargo.mjs clippy -p desegnos-ai --all-targets --all-features -- -D warnings`. The tests use real task-owned loopback HTTP servers through the same reqwest client, dummy credentials and isolated vault adapters. They check decoded attachment equality, mode/hash/schema, streaming/progress/usage, refusals and protocol failures, HTTP errors, cancellation/deadline, no retry after uncertain submission, redirect isolation, input/context/cost/output bounds, model-access GET and redaction. Credential tests cover explicit session fallback, replacement, removal, failed deletion and masked views. They never call OpenAI or inspect a real credential store.

The explicit `test-support` feature adds provider/ChatGPT literal-loopback constructors and isolated vault adapters. Provider loopback accepts HTTP, an explicit port, literal 127.0.0.1 or ::1 and `/v1`; OAuth accepts literal127.0.0.1 with an explicit port and root path only. They reject credentials, query strings, alternate paths and remote hosts. A compile-time error rejects this feature in release builds. Native test authorization is intercepted only in that guarded build. Normal builds expose no endpoint override, test vault or WebDriver server.

The opt-in `scripts/test-vault.mjs` check verifies actual Linux Secret Service with synthetic API and OAuth credentials on a guarded private bus/XDG profile: signed consent callback, system token bundles, rotation, fresh processes, daemon restarts and revocation/removal. Ordinary tests use isolated vaults. Live OpenAI consent/generation and Windows/macOS native/vault behavior remain distinct checks requiring the appropriate environment and private user action.

The settings-component regression runs with `node tests/ai-models-browser.test.mjs`. It uses an isolated headless Chromium profile, a private Vite port and dummy account data to verify new-model selection, saving, refresh and account switching. Set `CHROMIUM` to an alternate Chromium executable when needed; it never opens the desktop app or calls OpenAI.
